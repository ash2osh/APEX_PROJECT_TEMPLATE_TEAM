## Global Constraints

- APEX release line: 26.2; qualified APEX SQLcl floor: 26.3.0.0.
- Python 3.10+, standard library only; Bash 4.3+ and PowerShell 5.1+ parity.
- No custom database metadata tables, mutexes, checkout rosters, or ledgers.
- Credentials stay in saved SQLcl connections; no credentials in tracked files.
- All application commands use numeric IDs and explicit workspace/schema mappings.
- Shared DEV remains runtime truth; Git branches do not isolate database state.
- Full imports remain the only staging/production deployment route.
- Existing migration and ORDS export contracts remain unchanged.
- Keep drift checks, version stamps, exact source verification, and fail-closed
  baseline advancement. Full publish retains its whole-app guard; partial mode
  uses the reviewed selected-page guard and fresh whole-app verification snapshot.
- No automatic supporting-object installation, workflow-instance migration,
  theme upgrade, compatibility-mode change, or AI-provider conversion.
- Read `docs/known-limitations.md` before modifying accepted behavior.
- Commit and push only when explicitly requested.
- Run forced Oracle skills synchronization at least every seven days, with
  a check at the start of every task, automatic refresh when due, verified
  SQLcl-owned repository and installation timestamps, verified current-run
  completion/conflict checks, current-chat notification, and release-specific
  APEXlang skills. No extra timestamp file; inactive checkouts check freshness
  at their next task startup.

## Review Focus

1. Two processes using the same workspace developer must not be described as
   exclusively serialized; existing locks and recovery ownership are respected.
2. A skipped/failed import or failure after a database write preserves the old
   baseline and reports an unknown/unverified write rather than claiming rollback.
3. Deployment salt/override changes must be verified without exposing salt values
   or silently treating an ignored default deployment file as verified source.
4. Release conversion, binary files, and translated apps must survive export
   structure changes without overwriting authored descriptors or unrelated edits.
5. Partial selection cannot publish or advance the baseline for unselected dirty
   files, accept path escapes, or run against staging/production.

Each focus has tests in its owning task below. Qualification outcomes feed
explicit plan amendments rather than speculative SQLcl flags or package behavior.
